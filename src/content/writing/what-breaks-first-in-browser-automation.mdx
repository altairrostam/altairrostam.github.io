## Context

Browser automation is tempting because it can operate where APIs are missing or incomplete. The cost is that the browser becomes an integration surface with human-oriented behavior.

## What Changed

Reliability improved once scripts were wrapped in state checks, retries, evidence capture, and clear failure categories.

## System Implications

The automation layer needs monitoring like any other production dependency. It should report what it saw, what it tried, and where the page differed from expectations.

## Practical Takeaway

Treat browser automation like a negotiation with a changing interface, not a static script.
