## Overview

This project explored how to make a large catalog of models and datasets searchable without pretending that one retrieval strategy could carry every query. The system combined exact filters, keyword scoring, metadata ranking, and vector similarity into one explainable search experience.

## Problem

Pure semantic search worked well for fuzzy intent, but it regularly missed exact identifiers, benchmark names, licenses, and domain-specific abbreviations. Users needed both discovery and precision.

## Architecture

The architecture separated ingestion, enrichment, indexing, and query-time ranking. Metadata normalization happened before embeddings were generated, then each item was stored with structured fields and vector representations.

## Tradeoffs

The main tradeoff was accepting a more complex ranking pipeline in exchange for higher trust. A single vector score was simpler to operate, but it made failures harder to explain and tune.

## Technical Decisions

The system kept structured filters first-class instead of reducing everything into a prompt or embedding. This made query behavior more predictable for terms like modality, license, source, and update recency.

## Challenges

The hardest failures came from queries that mixed exact and fuzzy intent. A user might search for a model family, benchmark, provider, and task type in one line, and each part required a different retrieval signal.

## Lessons Learned

Search quality improved when ranking was treated as a product surface, not a hidden implementation detail. The useful version of the system made tradeoffs inspectable.
